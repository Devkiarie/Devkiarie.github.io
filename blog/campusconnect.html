CampusConnect - Building a Multi-Campus Social Network

Next.js 14 Express.js PostgreSQL Socket.IO Redis

Project Overview

CampusConnect is a full-stack social networking platform designed specifically for Kenyan university students. The goal was to create a space where students across multiple campuses could connect, collaborate, and share — with features tailored to campus life rather than generic social media.

The platform currently supports 3 campuses (JKUAT, University of Nairobi, Kenyatta University) and is deployed live in production. It handles real-time messaging, campus-scoped feeds, event management, community channels, and AI-powered features — all built as a monorepo with a clear separation between frontend and backend.

Architecture

The system is structured as a Turborepo + pnpm monorepo with clear boundaries:

  • apps/web — Next.js 14 frontend (App Router, Server Components)
  • apps/api — Express.js REST API with Socket.IO for real-time
  • database/ — Prisma ORM with PostgreSQL (Neon serverless)

Key architectural decisions that shaped the project:

  • Multi-campus feed scoping: Posts can target a specific campus or be broadcast globally. The feed API accepts a scope parameter (campus/general) so students see relevant content first.
  • Role-based access: 8 hierarchical roles from STUDENT up to SUPER_ADMIN, with campus-specific permissions (a Campus Admin at JKUAT can't moderate UoN content).
  • Real-time via Redis adapter: Socket.IO with Redis pub/sub ensures message delivery scales beyond a single server instance.
  • Non-blocking service init: External services (Meilisearch, workers) are wrapped in 5-second timeouts so the API always starts even if a dependency is unavailable.

Key Features

Real-Time Messaging

Private and group messaging built on Socket.IO with Redis adapter for horizontal scaling. Messages are persisted to PostgreSQL and delivered in real-time. Typing indicators, read receipts, and online presence are all handled via WebSocket events.

Campus Map with Routing

An interactive map (MapLibre GL) showing 10+ campus buildings with category-specific icons. For short distances (<2km), direct Haversine paths are used; longer routes go through OSRM for proper pedestrian routing.

AI-Powered Features

Integrated Google Gemini (1500 req/day free tier) for:

  • Trending topic detection from post content
  • Sentiment analysis on community discussions
  • Smart reply suggestions in messaging
  • Automatic summarization of long threads

Communities and Events

Students can create and join communities (clubs, study groups, course channels). Each community has its own feed and channel system. Events support RSVP, calendar integration, and location tagging on the campus map.

Technical Stack

  • Frontend: Next.js 14, TypeScript, Tailwind CSS, MapLibre GL
  • Backend: Express.js, Socket.IO, Prisma ORM
  • Database: PostgreSQL 16 (Neon), Redis 7 (Upstash)
  • AI: Google Gemini API
  • Media: Cloudinary (image uploads + transformation)
  • Email: Resend (transactional emails)
  • Deployment: Vercel (frontend) + Fly.io (API) + Neon (DB)

Key Challenges

Prisma on Serverless Platforms

Prisma v5.22.0 generates platform-specific binaries. On Render/Fly.io, the binary paths don't match monorepo layouts. Solution: explicitly run npx prisma@5.22.0 generate --schema=database/prisma/schema.prisma from the repo root during build.

Multi-Campus Data Isolation

Balancing data isolation (campus-specific content) with discoverability (cross-campus events, general feed). Solved with a dual-scope feed system — every post has a visibility scope, and the API filters accordingly without duplicating data.

Real-Time at Scale on Free Tier

Socket.IO with Redis adapter works well for horizontal scaling, but Upstash Redis (serverless) adds latency. Optimized by batching presence updates and using local memory for typing indicators with Redis only for cross-instance events.

Results

  • Deployed and live at campusconnect-pi-ten.vercel.app
  • 3 campuses, 8 role levels, 10+ mapped buildings
  • Full PWA — installable, offline caching for static assets
  • Sub-second message delivery via WebSocket
  • Zero-cost hosting stack (Vercel + Fly.io + Neon + Upstash free tiers)

Lessons Learned

  • Monorepos shine for full-stack projects — shared types, single CI, atomic deploys
  • Pin your ORM version. Prisma v7 broke everything; staying on v5.22.0 was the right call
  • Non-critical services should never block startup — 5s timeout pattern saved many cold starts
  • Build for multi-tenancy from day one, even if you start with one campus
